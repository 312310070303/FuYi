## 0. 结论摘要

1. **可行性：高**。悬浮窗、截屏、离线 OCR、LLM 翻译都是 Android 公开能力，Android 11+ 无需 root。
2. **关键门槛已过**：你已确认「游戏内可以正常截屏」→ 游戏没有启用 `FLAG_SECURE`，手机端方案成立。
3. **新增变量：联网游戏**。反作弊可能检测无障碍/悬浮窗（概率低但要防），加速器/VPN 可能影响翻译 API 网络（可分流解决）。
4. **推荐策略**：先用现成开源方案试 10 分钟；不满足（交互、术语、竖排、API 自由度）再按本 PRD 开发。
5. **投入**：MVP 约 8–12 人日；API 成本约 ¥1–6/局。

## 1. 背景与目标

### 1.1 背景

目标游戏为日文原版、无官方汉化，且必须联网。玩家希望在**不切出游戏、不查攻略**的前提下看懂剧情对话、菜单、技能与任务提示。现有做法（切出去用翻译 App、拍照翻译、对照攻略）都会打断节奏。

### 1.2 产品目标（量化）

| 指标 | 目标 |
|---|---|
| 单次翻译端到端延迟 | P50 ≤ 1.5s，P90 ≤ 3s（不含用户框选时间） |
| 日文识别准确率 | 标准字体、1080p、对话区域 ≥ 90% |
| 连续使用稳定性 | 30 分钟不闪退、服务不被杀 |
| 功耗 | 30 分钟约 100 次翻译，耗电 ≤ 5% |
| 安装包体积 | ≤ 40MB |
| 隐私 | 默认只上传 OCR 文本，截图不出设备 |

### 1.3 非目标

- iOS：系统不允许跨应用悬浮窗，也无法截取其他 App 画面。
- 游戏内文本 Hook / 内存读取：需 root 或注入，封号风险高。
- 全屏实时字幕：V1 按需触发，V2 再评估。
- 账号体系、云同步、社区功能。

## 2. 用户与场景

### 2.1 用户画像

- 小米手机用户，Android 12–16（HyperOS 1–3）。
- 玩日文原版联网游戏（JRPG、二次元手游、AVG、策略类）。
- 不要求逐字精准，要求「看得懂、不打断节奏」。
- 愿意配置一次 API Key，之后零操作。

### 2.2 核心场景

| 场景 | 文本特征 | 关键要求 |
|---|---|---|
| 剧情对话 | 长句、口语、角色语气 | 准确、连贯、术语统一 |
| 菜单 / 道具 / 技能 | 短词、专有名词多 | 术语表、译文简短 |
| 战斗 / 任务提示 | 短句、出现快 | 低延迟、不遮挡 |
| 公告 / 活动页 | 大段排版文本 | 整块识别、分行 |
| 竖排 / 漫画式对话框 | 竖排、描边字 | 方向识别、预处理（难点） |

### 2.3 联网游戏的特殊考虑

| 关注点 | 说明 | 对策 |
|---|---|---|
| 反作弊检测 | 部分反作弊 SDK 会检测无障碍服务、悬浮窗、录屏 | 只读屏幕，不注入、不改内存、不改包；PvP/排位时关闭 |
| 账号风险 | 理论上有误判可能 | 介意的话先用小号试；异常立即停用 |
| 网络共存 | 游戏加速器 / VPN 可能把 API 请求也代理走，导致变慢或失败 | 加速器设置里把翻译 API 域名设为直连/分流 |
| 带宽 | 翻译请求很小（每次几 KB），对游戏延迟影响可忽略 | 无需特殊处理 |
| 登录/支付页 | 可能单独启用 FLAG_SECURE，截出来是黑的 | 属正常现象，不影响游戏内使用 |

## 3. 现有方案对比

| 方案 | 能力 | 优点 | 不足 | 适用 |
|---|---|---|---|---|
| overlay-translator（开源） | 悬浮译文、端侧/云 OCR、多翻译源 | 免费、无 root、现成 | UI 与术语控制有限、竖排一般 | **先验证** |
| 商店类悬浮翻译 App | 悬浮球 + 区域 OCR | 上手快 | 广告/订阅、API 不可换、隐私 | 轻度使用 |
| Google Lens / 系统翻译 | 截屏后翻译 | 准确 | 不能悬浮，需切应用 | 偶尔查词 |
| PC：Translumo / LunaTranslator / 团子 | 屏幕 OCR 覆盖 | 效果最好、稳定 | 需电脑；手机游戏要模拟器/投屏 | 有条件首选 |
| **本方案（自研）** | 定制交互 + 术语 + 任意 API | 贴合习惯、可迭代 | 需开发与适配 | 长期玩 |

**结论**：先花 10 分钟验证现成方案；不满足再自研。自研的核心差异点是「点选文字块一键译 + 术语表 + 任意 LLM + 中文 UI」。

## 5. 用户体验流程

### 5.1 首次配置（约 2 分钟）

1. 安装 APK → 打开「浮译」。
2. 授予「显示悬浮窗」。
3. 开启「无障碍服务」。
4. 选择翻译服务（DeepSeek / OpenAI / Gemini / 硅基流动 / 自定义），填 Key 与模型，点「测试」。
5. 按小米清单开启自启动、省电无限制、后台弹出界面、锁定后台。
6. 点「启动悬浮球」，回到游戏。

### 5.2 单次翻译

1. 点悬浮球（球短暂隐藏，避免被截进去）。
2. 约 100ms 后抓取一帧，全屏显示冻结画面（压暗）。
3. 后台同时识别整屏文字块，0.5s 内用细框标出。
4. 用户操作二选一：
   - **点**某个文字块 → 直接翻译该块文本；
   - **拖**一个矩形 → 只识别选区。
5. 识别 → 翻译（约 0.8–1.5s）→ 结果卡从选区旁弹出。
6. 结果卡：原文小字、译文大字；可复制 / 重译 / 关闭；可拖动位置。
7. 关闭后悬浮球恢复。

### 5.3 状态反馈

| 状态 | 反馈 |
|---|---|
| 抓屏中 | 悬浮球变灰 + 轻微震动 |
| 识别中 | 选区上方「识别中…」 |
| 翻译中 | 结果卡骨架 + 「翻译中…」 |
| 成功 | 译文 + 可选显示耗时 |
| 失败 | 错误原因 + 重试按钮 |

### 5.4 异常与恢复

| 现象 | 原因 | 处理 |
|---|---|---|
| 全黑 | 该界面启用了 FLAG_SECURE | 提示无解，建议换界面/PC |
| 截屏失败 | 无障碍被系统关闭 | 引导重开 |
| 无文字 | 选区空白或字体过花 | 提示重选 |
| 401 / 402 | Key 错误 / 余额不足 | 原样显示服务商错误 |
| 超时 | 网络差（加速器/VPN） | 重试 1 次，仍失败则提示分流 |
| 悬浮球消失 | 后台被杀 | 通知栏常驻，点击重启 |

| 环节 | 预算 |

| 抓屏（takeScreenshot） | 80–150ms |

- 按需抓屏，不做常驻录屏。
- OCR 仅在点击时运行。
- 预估 100 次翻译 < 5% 电量。

### 7.3 兼容性

- Android 11–16；MIUI 13–14、HyperOS 1–3。
- 分辨率 1080×2400 ～ 1440×3200。
- 横屏 / 竖屏 / 挖孔 / 刘海。

### 7.4 隐私与安全

- API Key 存应用私有目录，可选用 EncryptedSharedPreferences。
- 只上传 OCR 文本；截图不出设备。
- 不采集埋点、不申请无关权限。
- 侧载分发，不上架应用商店（无障碍 + 悬浮窗组合审核麻烦）。

### 7.5 可用性

- 全中文界面，字号大、对比度 ≥ 4.5:1。
- 单手可达：悬浮球默认右侧中部。
- 所有失败都有中文解释与下一步动作。

### 7.6 包体积

- ML Kit 日文 bundled 模型约 20MB，总包预计 30–35MB。

## 8. 技术方案

### 8.1 总体架构

```
┌──────────────────── 小米手机 ────────────────────┐
│  游戏（全屏 SurfaceView / GL）                     │
│         ▲ 悬浮窗 TYPE_APPLICATION_OVERLAY          │
│  ┌──────┴─────────────────────────────────┐      │
│  │ OverlayService（前台服务）               │      │
│  │  · 悬浮球   · 选区层   · 结果卡          │      │
│  └──────┬──────────────────┬──────────────┘      │
│         │ 请求一帧           │ 文本                │
│  ┌──────▼───────┐    ┌──────▼──────┐              │
│  │CaptureService│    │  OcrEngine  │              │
│  │无障碍截屏     │    │  ML Kit 日文 │              │
│  └──────────────┘    └──────┬──────┘              │
│                              │ 日文                │
│                       ┌──────▼──────┐             │
│                       │ Translator  │──HTTPS──▶ LLM API
│                       └─────────────┘             │
└───────────────────────────────────────────────────┘
```

### 8.2 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | Kotlin | 官方、简洁、生态好 |
| UI | 原生 View + Material 3 | 悬浮窗必须走 WindowManager，Compose 不适合 |
| 截屏 | `AccessibilityService.takeScreenshot` | 免每次授权，可在游戏上直接抓 |
| OCR | ML Kit 日文（bundled） | 离线、免费、国行无 GMS 可用 |
| 翻译 | OpenAI 兼容 HTTP API | 一套代码接多家（DeepSeek/OpenAI/Gemini/硅基流动） |
| 存储 | SharedPreferences（V1）/ Room（V1.1 缓存） | 轻量 |
| 构建 | AGP 8.7 / Gradle 8.9 / JDK 17 | 稳定组合 |
| 最低版本 | API 30（Android 11） | 无障碍截屏的硬性要求 |

### 8.3 权限模型

| 权限 | 用途 | 获取方式 | 小米注意 |
|---|---|---|---|
| `SYSTEM_ALERT_WINDOW` | 悬浮窗 | 系统设置页 | 「显示悬浮窗」是独立开关 |
| `BIND_ACCESSIBILITY_SERVICE` | 截屏 | 无障碍设置 | 部分机型重启后自动关闭 |
| `FOREGROUND_SERVICE` + `SPECIAL_USE` | 常驻 | 自动 | Android 14+ 需声明类型 |
| `POST_NOTIFICATIONS` | 常驻通知 | 运行时授权 | Android 13+ |
| `INTERNET` | 翻译 | 自动 | — |
| 后台弹出界面（MIUI） | 从后台拉起页面 | 系统设置页 | 非标准权限，小米特有 |

### 8.4 截屏子系统

#### 8.4.1 首选：无障碍截屏

- API：`AccessibilityService.takeScreenshot(displayId, executor, callback)`（API 30+）。
- 配置：无障碍服务 XML 中声明 `android:canTakeScreenshot="true"`。
- 返回 `ScreenshotResult` → `HardwareBuffer` → `Bitmap.wrapHardwareBuffer()` → 拷贝为 `ARGB_8888` → **关闭 HardwareBuffer**。
- 频率限制：调用过快返回 `ERROR_TAKE_SCREENSHOT_INTERVAL_TIME_SHORT`；实现约 400ms 节流 + 一次延迟重试。
- `FLAG_SECURE` 区域为黑（游戏内已确认不涉及）。
- 优点：不需要每次弹授权，适合「点一下译一句」。

#### 8.4.2 备选：MediaProjection

- 触发条件：无障碍不可用、或 V1.1 的连续模式。
- 代价：Android 14+ 每次会话都要用户确认；需 `mediaProjection` 前台服务类型；Android 15+ 状态栏有共享提示。
- 结论：V1 不做，V1.1 视需要补。

#### 8.4.3 FLAG_SECURE 兜底

- 应用内无法可靠读取窗口标志。
- 判定：抓帧后检测是否整屏纯黑/单色（采样方差），是则提示「该界面禁止截屏」。
- 兜底路径：root + LSPosed 去标志 / PC 模拟器 / 换设备。

### 8.5 悬浮窗体系

| 窗口 | 尺寸 | 焦点 | 关键 Flag | 说明 |
|---|---|---|---|---|
| 悬浮球 | 56dp | 否 | `NOT_FOCUSABLE`、`LAYOUT_NO_LIMITS` | 可拖动，点击抓屏 |
| 选区层 | 全屏 | 是 | `LAYOUT_IN_SCREEN`、`LAYOUT_NO_LIMITS` | 接收返回键取消 |
| 结果卡 | 屏宽-32dp，最大 380dp | 否 | `NOT_FOCUSABLE` | 按钮可点，标题区可拖 |

- 坐标映射：截图与视图按比例缩放；裁剪前先 clamp 到图内。
- 返回键：选区层 `onKeyDown(KEYCODE_BACK)` 取消，恢复悬浮球。
- 层级：`TYPE_APPLICATION_OVERLAY` 位于应用之上、状态栏/通知栏之下。
- 少部分应用会调用 `Window.setHideOverlayWindows(true)` 隐藏悬浮窗（游戏少见，遇到无法绕过）。

### 8.6 OCR 管线

1. 输入：整屏 Bitmap（抓帧）或裁剪区。
2. 预处理（按需）：放大 2×、灰度、对比度拉伸、Otsu 二值化。
3. 识别：ML Kit 日文；整屏约 0.3–0.7s，裁剪区 0.1–0.2s。
4. 后处理：
   - 去掉 CJK 字符之间的空格；
   - 同一对话块的多行按 x 重叠 + 行距合并；
   - 过滤 < 2 字符的噪声块。
5. 输出：`List<TextBlock(rect, text)>`。

### 8.7 翻译管线

- 协议：`POST {base}/chat/completions`（OpenAI 兼容）。
- 预设：DeepSeek / OpenAI / Gemini（OpenAI 兼容端点）/ 硅基流动 / 自定义。
- 超时：连接 15s、读取 60s；5xx / 网络错误重试 1 次。
- 提示词（V1）：

```text
你是资深日文游戏本地化译者，把用户给的日文游戏文本翻译成简体中文。
规则：
1. 只输出译文，不解释、不加引号、不注音。
2. 人名、地名、技能名前后统一，严格遵守术语表。
3. 保留角色语气（敬语/粗鲁/傲娇/古风），口语自然。
4. 菜单、选项、技能名尽量短。
5. 拟声词用中文习惯表达。
6. 原文含英文缩写/错误码时保留原文。
术语表（原文=译文）：
{glossary}
```

- 术语表：设置页每行 `原文=译文`，注入 system prompt，上限 200 条。
- 上下文：携带最近 2 条原文 + 译文（V1.1），帮助代词与语气连贯。
- 缓存：`SHA-256(model + promptVersion + text)` → 译文（V1.1）。
- 失败降级：展示原文 + 错误原因 + 重试按钮。

## 10. 小米 / HyperOS 适配清单

首次使用需手动设置：

1. 设置 → 应用设置 → 应用管理 → 浮译 → 权限管理 → **显示悬浮窗**：允许。
2. 同页 → **后台弹出界面**：允许。
3. 应用信息 → **省电策略**：无限制。
4. 应用信息 → **自启动**：允许。
5. 最近任务 → 下拉**锁定**浮译。
6. 设置 → 更多设置 → **无障碍** → 已下载的应用 → 浮译：开启。
7. 游戏加速：把浮译加入白名单，或关闭「防打扰」。
8. 安装时允许「未知来源应用」。

已知差异：

- HyperOS 2/3（Android 15/16）对 MediaProjection 限制更严 → 用无障碍截屏规避。
- 国行无 GMS → 必须用 bundled OCR 模型，不能依赖 Google Play 服务下载模型。
- 部分机型重启后无障碍自动关闭 → 每次开机自检并提示。

## 13. 验收标准（DoD）

- [ ] 点文字块可直接出译文。
- [ ] 端到端 P50 ≤ 2s。
- [ ] 术语表在译文中生效。
- [ ] 断网 / 401 / 超时有明确中文提示。
- [ ] 连续 30 分钟不崩、服务不被杀。
- [ ] 返回键可取消选区。

## 15. 决策建议

1. **先做 M0（约 10 分钟）**：装 overlay-translator，在你那款游戏里试 10 分钟，看延迟、识别率、术语是否够用。
2. **够用** → 直接用，省下 1–2 周开发。
3. **不够用** → 按本 PRD 开发 V1（AI 辅助下约 2–4 天出可安装 APK）。
4. **若后续遇到黑屏界面**（登录/支付页）→ 属正常，不影响游戏内使用。
